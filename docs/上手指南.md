# 上手指南：从零到装进手机

这份文档是给「会一点 Python、想全程参与、但让 AI 写代码」的你准备的。
每个命令都写清楚**为什么跑、会看到什么、怎么判断成功**。

---

## 一、先认识工具链：四样东西各干什么

很多人卡在第一步不是因为难，而是不知道这几个东西为什么要装。

| 工具 | 干什么 | 类比 |
| --- | --- | --- |
| **JDK 17** | 安卓构建系统自己是用 Java 写的，构建时要用它 | 工地上必须有的发电机 |
| **Flutter SDK** | 你写代码用的框架 + 编译器。它自带 Dart 语言 | 你的车间 + 机床 |
| **Android SDK** | 把编译结果打包成 `.apk`，还负责连手机调试 | 打包机 + 装车设备 |
| **keystore** | 给 APK 签名。安卓只肯安装「有签名」的 app | 出厂合格章 |

你机器上 JDK 17 已经有了，缺 Flutter SDK 和 Android SDK（合计约 2.7 GB）。

> **为什么要装这么多？** 因为安卓不是「解释执行」的平台。你的代码必须被编译成
> 机器能跑的包，再签名，系统才认。这一步省不掉，但装一次就够了。

## 二、目录结构：代码都在哪

```
D:\project\phone_app\
├─ IDEA.md              设计稿（需求、数据模型、视觉规范都在这）
├─ docs\上手指南.md      当前这份文档
├─ lib\                 ★ 你写的全部代码
│  ├─ main.dart             程序入口：初始化数据库 → 启动界面
│  ├─ app_globals.dart      全局单例（数据库、图片仓库）
│  ├─ theme\app_theme.dart  配色、间距、字号——所有视觉参数的唯一出处
│  ├─ models\               数据结构：卡片、科目
│  ├─ data\                 数据层：建库、读写、导出
│  ├─ widgets\              可复用的小组件（列表行、空状态）
│  └─ features\             按功能分的页面
│     ├─ home\              首页六宫格 + 全局搜索
│     ├─ formula\           公式手册：列表 / 详情 / 编辑
│     ├─ subjects\          科目管理
│     ├─ trash\             最近删除
│     ├─ export\            导出
│     └─ placeholder\       五个「待开发」占位页
├─ test\                自动化测试
└─ android\             flutter create 生成的安卓工程（不用手改）
```

**读懂这个结构，你就读懂了整个 app 的骨架：**

界面（features）→ 数据层（data）→ 数据库（SQLite 文件）

界面永远不直接写 SQL，都通过 `data/card_repository.dart` 走。
这条规矩让以后加「灵感记录」「错题本」时，不用重写数据层。

## 三、分步操作

下面每一步我都会陪你跑。命令可以你自己复制执行，也可以让我跑。

### 第 1 步：装 Flutter SDK

```powershell
# 解压已经下载好的 SDK 到 C:\src\flutter
tar -xf $env:TEMP\flutter-stable.zip -C C:\src

# 验证装好了（第一次跑会慢一点，它要自己初始化）
C:\src\flutter\bin\flutter.bat --version
```

**会看到**：类似 `Flutter 3.47.5 • channel stable • Dart 3.x` 的版本信息。

**这一步在干什么**：Flutter SDK 是一个文件夹，里面装着编译工具、Dart 语言运行时
和一堆预编译库。不需要「安装」，解压 + 加到 PATH 就能用。

### 第 2 步：装 Android SDK

Flutter 本身不会打安卓包，它调用 Android SDK 里的工具干活。

```powershell
# 下载 commandline-tools（官方命令行版，比装 Android Studio 轻得多）
# 然后用 sdkmanager 装四个组件
sdkmanager "platform-tools" "platforms;android-36" "build-tools;36.0.0"

# 接受许可协议（会问好几遍 y）
sdkmanager --licenses
```

**为什么要 `--licenses`**：安卓 SDK 的每个组件都有法律协议，必须显式同意，
否则构建时会直接报错退出。

### 第 3 步：体检

```powershell
flutter doctor
```

**会看到**：一份清单，打勾的就是好了。理想结果：

```
[√] Flutter
[√] Android toolchain
[√] Android Studio   ← 这条没装 Studio 会是 [!]，不影响打 APK
[√] Connected device
```

**判断成功**：`Android toolchain` 和 `Flutter` 打勾就够开工了。

### 第 4 步：拉依赖

```powershell
flutter pub get
```

**这一步在干什么**：App 用了几个开源库（存数据用 `sqflite`、拍照用
`image_picker`、导出打包用 `archive`……）。`pub get` 按 `pubspec.yaml` 里的
清单把它们下到本地。类比 Python 的 `pip install -r requirements.txt`。

### 第 5 步：跑测试

```powershell
flutter test
```

**会看到**：一串测试名后面跟 `+1`、`+2`……最后 `All tests passed!`

**为什么先跑测试再打包**：测试能在 10 秒内告诉你「数据和导出逻辑有没有写错」，
而打包要几分钟。先跑便宜的那一步。

### 第 6 步：出包

```powershell
flutter build apk --release
```

**产物**：`build\app\outputs\flutter-apk\app-release.apk`

`--release` 和 `--debug` 的区别：debug 包里塞了调试器，又大又慢，
是给开发时用的；release 包做了压缩和优化，是真正给人用的。

### 第 7 步：装到手机

1. 把 `app-release.apk` 通过微信文件传输助手 / 数据线 / 网盘传到手机
2. 手机上点开这个文件，系统会提示「未知来源应用」，允许一次
3. 装完桌面就会出现「万能百宝箱」

**为什么会有「未知来源」警告**：这个 APK 不是从应用商店装的，安卓默认不信任。
你自己签的名，自己负责，正常现象。

## 四、你可以自己动手试的几个小实验

光看不算学会。下面几个改动都只改一行，改完重新打包就能看到效果，
是理解「代码 → APK 」这条链路最快的办法。

### 实验 1：换个主色

打开 `lib/theme/app_theme.dart`，找到这一行：

```dart
primary: Color(0xFFB5834A),   // 暖棕
```

把 `0xFFB5834A` 改成 `0xFF4A6B52`（墨绿），重新打包。

**你会理解**：全局视觉是集中管理的。因为所有页面都从这里取色，
改一个数字，整个 app 的按钮、选中态、图钉全变色。
这就是「设计 token」的价值——也解释了为什么代码里不允许写死颜色。

### 实验 2：加一个科目

不用改代码：打开 app → 公式手册 → 筛选条最右边的编辑图标 → 添加科目。

**你会理解**：科目是存在数据库里的**数据**，不是写死在代码里的常量。
这也是为什么「删科目」只是把卡片变成未分类，而不是删卡片——
数据之间的关系要能安全地拆开。

### 实验 3：改一句提示文案

打开 `lib/features/formula/formula_list_screen.dart`，搜索 `还没有公式`，
改成你想说的话。

**你会理解**：`features/` 下的每个文件 = 一个页面。
页面里既有「长什么样」（build 方法）也有「点了会怎样」（那些 `_openXxx` 方法）。

### 实验 4：看数据库里到底存了什么

APP 装上后，数据在手机私有目录里，用电脑看不到。
但你可以用「导出 → 存到手机」，拿到 zip 解压看 `data.json`——
那就是数据库里全部内容的原样快照。

## 五、常见问题

**Q：`flutter doctor` 里 Android Studio 那条是红的，要装吗？**
不用。Android Studio 是个编辑器（类似 PyCharm），你用 VS Code 或记事本写代码都行。
只有打 APK 必须的组件才要装，那些属于 Android SDK。

**Q：打包报「Gradle download」卡住不动？**
构建时 Gradle（安卓的构建工具）要下载自己，走的还是那条慢网。
第一次会慢，下完就缓存在本机，之后快得多。

**Q：改了代码，手机上要重装吗？**
要。手动装 APK 的模式下，每次改动都要重新打包 + 重新传。
如果以后觉得烦，可以改成数据线连电脑调试，改完按一下就在手机上刷新。

**Q：数据会不会丢？**
数据存在 app 私有目录，**卸载 app 就全没了**。所以导出功能是刚需，
建议每个月导出一次存到网盘。

**Q：为什么不用 Python 写？**
Kivy + Buildozer 在 Windows 上打不出 APK，必须装 Linux 或 WSL。
为了打包先折腾一整天环境、一行业务代码没写，不值得。
Python 更适合用来处理导出的数据、写备份脚本。
